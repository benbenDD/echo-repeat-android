# v1.7.9 播放状态恢复设计

## 目标

修复应用退出后重新打开时无法自动回到上次播放条目的问题，同时区分后台播放服务仍存活和应用进程已被系统清理两种场景。

## 已确认的恢复语义

- 如果播放服务仍存活，重新打开应用时直接连接现有播放器，不重新加载音频；保留当前条目、绝对位置、分段、重复遍数及播放/暂停状态，并自动进入复读页。
- 如果播放进程已被清理，读取持久化的上次条目与最近播放进度，重建分段和字幕状态，自动进入复读页，但默认保持暂停，避免冷启动后突然发声。
- 用户从播放列表手动打开条目时保持原行为：装载后立即播放。
- 找不到上次条目、文件权限失效或条目不可用时停留在播放列表，不启动空播放器，并显示可理解的提示。

## 架构与数据流

1. `PlaybackSnapshot` 增加稳定的媒体 ID，用于新建的界面层识别仍在运行的播放服务所播放的数据库条目。
2. `MainViewModel` 在初始化时等待全局设置就绪，然后执行一次启动恢复：
   - 优先检查活动播放快照；若存在有效媒体 ID，则查询数据库并仅恢复界面当前条目，不发送 `ACTION_LOAD`。
   - 否则读取 `lastTrackId`，查询有效条目，构建字幕与分段，并以“装载但不播放”的方式恢复。
3. `ACTION_LOAD` 增加明确的自动播放参数；手动打开传入 `true`，冷启动恢复传入 `false`，不再由服务硬编码自动播放。
4. 播放服务负责周期性保存当前媒体 ID、绝对位置、分段索引、重复索引和播放意图，并在暂停、切段、任务移除及销毁前尽力刷新。
5. 数据库存储继续负责每个条目的长期进度；轻量级播放会话状态使用独立持久化存储，以免为会话字段扩展音频条目表。

## 状态边界

- “退出界面但服务仍活着”不重置重复遍数、不触发 seek、不打断音频。
- “进程死亡后的冷启动”恢复上次绝对位置和所在分段；重复遍数恢复到已保存值，但保持暂停。
- 已完成的音频不自动从末尾播放；恢复位置按现有可播放位置规则校正。
- 睡眠定时器仍沿用现有独立持久化逻辑，本版本不改变其到期语义。

## 测试策略

- 单元测试覆盖：活动服务快照优先、冷启动回退、无效媒体 ID、自动播放参数、重复序号归一化和持久化节流策略。
- 回归测试覆盖：手动打开仍自动播放、冷启动恢复默认暂停、活动服务重连不发送重新装载命令。
- 完整运行现有单元测试并构建 APK，校验 `versionName=1.7.9`、`versionCode=18` 和 APK v2 签名。
- 真机验收分别验证：返回桌面后重开、从最近任务划掉后重开、系统清理进程后重开，以及锁屏后台连续播放。

## 非目标

- 不实现开机后自动播放。
- 不改变播放列表排序、分段算法、字幕时间校准或睡眠定时规则。
- 不在冷启动时未经用户操作自动发声。
